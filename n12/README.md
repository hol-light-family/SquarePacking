# n = 12:  s(12) = 4

```
SQUARE_PACKING_SIDE_12 : |- square_packing_side 12 = &4
PACKS_12               : |- forall t. packs 12 t <=> &4 <= t
```

| file | content |
|---|---|
| `statement.ml` | the two theorems, every constant they use with its definition site, and the mechanical check |
| `PROOF_STRUCTURE.md` | the structure of the proof: upper bound, Phase 1 (reduction to 117 cases), Phase 2 (the cases), assembly |
| `make.ml` | the build (generated by `scripts/mk_final.py`), ending with `statement.ml` |
| `upper.ml`, `phase1/`, `geometry/`, `certlib/`, `cert/`, `cases/`, `assembly.ml` | the proof |
| `docs/` | `lean_comparison.md` (comparison with the Lean proof, and what the port found about the Lean sources), `audit.md` (an independent audit of the port), `cert_design.md` (the certificate checkers), `jatloe_cert_map.md` (the architecture of the Lean development), `build_2026-11-14.txt` (excerpts of the build logs) |
| `bounds/` | an earlier, independent result 7943/2000 ≤ s(12) ≤ 4 by weighted point covers (Evan Daniel's box-tree method); not needed for s(12) = 4 |

The proof is a port of the Lean 4 development by Jatloe, Gurevitch, Lewis and Ahmed
([Queuingtheorydotcom/Jatloe12SquaresFormalized](https://github.com/Queuingtheorydotcom/Jatloe12SquaresFormalized),
commit d0caf45; squaremath.org T-245), whose main theorem is
`N12Compact.Final.optimality : S12.packingConstant12 = 4`.  That development had not been
independently built or reviewed.  Every Lean statement used was re-proved here in HOL Light,
including:
- about 30 files that the Lean repository marks "source only, not compiled";
- the facts that Lean established with `native_decide`.

## Build

From the project root:

```
HOLLIGHT_DIR=/path/to/hol-light shared/build.sh n12/make.ml            # or: SQ_DOMAINS=4 HOLLIGHT_DIR=... shared/build.sh n12/make.ml
```

- **OCaml 5** is required: the parallel proof steps use OCaml 5 domains.
- **Parallelism.**  Each parallel proof step (the Phase 1 family enumeration and the
  certificate checkers) asks for at most 16 domains, and gets `min 16 cap` of them, where the
  cap is `SQ_DOMAINS` if set and otherwise `Domain.recommended_domain_count ()` (normally the
  number of cores).  The log prints the cap (`parallel steps use at most k domains`); with
  k ≥ 16 the build uses 16 domains, so more than 16 cores do not help.
  - With fewer domains the build is slower but proves the same theorems: parallelism changes
    only the speed, never the result.
- **Memory.**  The checked builds peaked at about 20 GB (see below), with 16 domains.  Each
  domain keeps its own copy of the computation tables, so fewer domains should need somewhat
  less (not measured).  Plan for at least 32 GB of RAM.
- **Python.**  The LP oracles `shared/tools/*.py` need SciPy (see the top-level README).

The log `n12/make.log` ends with:

```
assemble_s12: 117 of 117 retained rows proved, 0 assumed
FINAL hypotheses remaining: 0
FINAL RESULT CHECK passed: |- square_packing_side 12 = &4 with no hypotheses
FINAL check_axioms passed: only INFINITY_AX, SELECT_AX, ETA_AX
n=12 STATEMENT CHECKED: |- square_packing_side 12 = &4 (no hypotheses; axioms: INFINITY_AX, SELECT_AX, ETA_AX only)
```

## Data and scripts

All of the following is untrusted: a wrong value can only make a kernel check fail.

- `data/`: certificate data read by the build (`data/cert/`) and the Phase 1 enumeration
  certificate (`data/early_cert.txt`).
- `port_data/`: the registry of case theorems (`case_thms.txt`, read by `mk_final.py`), name
  aliases between Lean and HOL, and Phase 1 data extracted from Lean.
- `scripts/`:
  - the extractors that turn Lean sources into OCaml data (`*_extract.py`, `gen/`);
  - the certificate oracles (`*_oracle.py`);
  - the box-tree generator for `bounds/` (`gen_tree.py`);
  - `mk_final.py`, `done_order.py` and `ready.py`, which generate `make.ml`.  Regenerating
    `make.ml` requires the Lean sources in `ext/jatloe`, a gitignored clone of the repository
    above, because the file order comes from the Lean import graph.
- `bounds/data/` (gitignored): box trees for `bounds/make_bounds.ml` (see below).

## The earlier bounds 7943/2000 ≤ s(12) ≤ 4 (`bounds/`)

This result is independent of the proof of s(12) = 4 and is not part of `make.ml`.  The lower
bound replays a box tree, which is generated from a weighted point certificate in
`bounds/certs/` and is not in git.  From the project root:

```
python3 n12/scripts/gen_tree.py n12/bounds/certs/s12_lower_3.9715.txt n12/bounds/data/s12_3.9715r.dat \
    --look 0 --procs 30 --pdepth 15 --rects 1        # writes a 1.5 GB file
HOLLIGHT_DIR=/path/to/hol-light shared/build.sh n12/bounds/make_bounds.ml
```

- `gen_tree.py` is plain Python (no SciPy); `--procs` is the number of worker processes.
- `make_bounds.ml` reads the tree named by `SQ_CERT` (default
  `n12/bounds/data/s12_3.9715r.dat`).  It checks the tree on `SQ_DOMAINS` domains; unlike the
  main build, the default here is `Domain.recommended_domain_count () - 1`, and all of them
  are used.
- The log `n12/bounds/make_bounds.log` ends with
  `n=12 bounds STATEMENT CHECKED: |- &7943 / &2000 <= square_packing_side 12 /\ square_packing_side 12 <= &4 (...)`.
- On 2026-11-11 (before the repository was restructured) the check took 1 h 56 min with 92
  domains.
